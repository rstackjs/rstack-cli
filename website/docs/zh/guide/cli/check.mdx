# check

`rs check` 命令用于检查当前项目的 lint 和格式问题，也可以启用 TypeScript 类型检查。

## 用法 \{#usage}

```bash
rs check [options] [files...]
```

传入文件或目录，可以将 lint 和格式检查都限制在这些路径中：

```bash
rs check src/index.ts packages/utils
```

## 检查内容 \{#checks}

默认情况下，`rs check` 会先运行 [`rs lint`](./lint)，再运行 [`rs fmt --check`](./fmt#--check)，不会修改文件。即使 lint 或类型检查报告错误，也会继续检查格式，让你在一次运行中看到所有已启用检查的结果。

只有所有已启用的检查都通过，命令才会成功退出。如果遇到配置加载失败等导致检查无法运行的错误，命令可能会提前停止。

## 选项 \{#options}

### `--fix`

自动修复 lint 和格式问题：

```bash
rs check --fix
```

该选项会先运行 `rs lint --fix`，应用可用的 lint 修复。只有 lint 和已启用的类型检查都通过，才会继续运行 `rs fmt --write`，格式化修复后的文件。

### `--type-check`

在 lint 过程中启用 TypeScript 类型检查：

```bash
rs check --type-check
```

默认不启用类型检查。

### `-h, --help`

显示命令用法和选项信息，但不运行检查：

```bash
rs check --help
```

## 配置 \{#configuration}

`rs check` 没有独立的 `define.check()` 配置。它会使用 [`define.lint()`](../configuration#define-lint) 中的 lint 配置，以及 [`define.fmt()`](../configuration#define-fmt) 中的格式化配置。
